```python
import pyvis
from pyvis.network import Network

def build_interactive_graph(graph: dict) -> Network:
    net = Network(height="600px", width="100%", bgcolor="#ffffff")
    
    # 按教材来源设置颜色
    color_map = {"教材1": "#ff6b6b", "教材2": "#4ecdc4", ...}
    
    for node in graph["nodes"]:
        count = node.get("source_count", 1)
        size = 10 + count * 5  # 频次越高节点越大
        net.add_node(node["id"], 
                     label=node["name"],
                     size=size,
                     color=color_map.get(node["source_textbook"], "#999"))
    
    for edge in graph["edges"]:
        net.add_edge(edge["source"], edge["target"], 
                    title=edge["description"])
    
    return net
```

```python
def calculate_compression_ratio(textbooks: list, essence: dict) -> dict:
    original_chars = sum(b.get("total_chars", 0) for b in textbooks)
    essence_chars = essence.get("selected_chars", 0)
    return {
        "original": original_chars,
        "essence": essence_chars,
        "ratio": essence_chars / original_chars if original_chars else 0,
        "target_met": essence_chars / original_chars <= 0.30
```

### 3.1 RAG Pipeline 优化（+4 分）

**当前实现**：基础分块 + 本地检索

**进阶要求**：
| 要求 | 实现方案 | 难度 |
|------|----------|------|
| 分块 + embedding + 检索说明 | 已实现 | — |
| BM25 混合检索 | `rank_bm25` 库 | ⭐ |
| rerank 模型优化 | BGE-reranker | ⭐⭐ |

**代码示例**：
```python
# src/rag.py 增强
from rank_bm25 import BM25Okapi
import numpy as np

def hybrid_search(query: str, chunks: list, top_k: int = 5):
    # 1. BM25 召回
    bm25_scores = bm25_model.get_scores(tokenize(query))
    bm25_top = np.argsort(bm25_scores)[-top_k:]
    
    # 2. Embedding 召回
    embed_scores = compute_cosine_similarity(
        embed_model.encode(query), 
        embed_model.encode([c["text"] for c in chunks])
    )
    embed_top = np.argsort(embed_scores)[-top_k:]
    
    # 3. RRF 融合
    final_scores = {}
    for rank, idx in enumerate(bm25_top):
        final_scores[idx] = final_scores.get(idx, 0) + 1 / (60 + rank)
    for rank, idx in enumerate(embed_top):
        final_scores[idx] = final_scores.get(idx, 0) + 1 / (60 + rank)
    
    return sorted(final_scores.items(), key=lambda x: x[1], reverse=True)[:top_k]
```

```markdown
## 3. 设计决策论证

### 3.1 为什么选择单体应用而非多 Agent 框架？

**考量因素**：
1. **部署风险**：5 小时黑客松场景下，LangGraph 等框架增加调试成本
2. **上下文限制**：多 Agent 通信增加 token 消耗
3. **可替换性**：逻辑上保留 Agent 接口，后续可平滑迁移

**取舍分析**：
| 方案 | 开发速度 | 可扩展性 | token 效率 |
|------|----------|----------|------------|
| 单体 + 模块化 | ⭐⭐⭐⭐⭐ | ⭐⭐ | ⭐⭐⭐⭐⭐ |
| LangGraph 多 Agent | ⭐⭐ | ⭐⭐⭐⭐⭐ | ⭐⭐⭐ |

结论：MVP 阶段优先保证功能完整性，选择单体架构。

### 3.2 为什么使用 Streamlit 而非 FastAPI + React？

**考量因素**：
1. 开发效率：Streamlit 5 倍于 React 的开发速度
2. 赛题要求：Web 应用可用即可，不强制 SPA
3. 资源限制：魔搭创空间 CPU 部署 Streamlit 更轻量

### 3.3 RAG 策略选择

**为什么不只用向量检索？**
- 精确术语匹配场景下，BM25 优于 embedding
- 混合检索可覆盖两种情况

**为什么不加 rerank？**
- 模型推理耗时增加
- 当前数据集规模下收益有限
- 后续可作为优化点
```
